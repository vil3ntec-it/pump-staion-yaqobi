# ثبت‌نام و ورود — دو گام، و کارِ سرور

گزارشِ صریحِ صاحب ریپو (۱۴۰۵/۰۶/۲۸):

> «نه می‌گوید حساب داری یا نه، نه ثبت یا ساختنِ حساب دارد و نه رمز دارد و
> می‌خواهد — خیلی اشتباه درست شده. اول اسم، ایمیل، رمز، تکرارِ رمز؛ بعد برود
> بخشِ بعدی: کدِ شش‌رقمی و تاییدِ آن از سرور و اسمِ پمپ و لوکیشنِ پمپ. همین و
> بعد هم تمام.»

## گام‌ها (کارتِ بالای «پروفایل»)

```
گامِ ۱  حساب   ‹حساب می‌سازم | حساب دارم›   نام · ایمیل · رمز · تکرارِ رمز
               └── یا «ورود با گوگل»   └── یا «بعداً» (بی‌اینترنت)
گامِ ۲  پمپ    کدِ شش‌رقمی → تاییدِ سرور · نامِ پمپ · لوکیشنِ پمپ
گامِ ۳  تمام   خلاصه، و دو دکمهٔ «تغییرِ حساب / تغییرِ پمپ»
```

- گامِ جاری از **حالِ واقعیِ برنامه** حساب می‌شود، نه از حافظهٔ صفحه
  (`AccountSectionViewModel.ShowLogin`): وارد شده؟ فعال شده؟ نامِ پمپ دارد؟
  پس با بسته و باز شدنِ برنامه همان‌جایی است که باید باشد.
- ⚠️ **رمز هیچ‌جا روی این کامپیوتر نمی‌نشیند** — نه خام، نه هش. فقط همان یک
  بار به ابر می‌رود و توکنِ نشست برمی‌گردد؛ بعد از هر گام از حافظهٔ صفحه هم
  پاک می‌شود. آزمونِ `RamzeAbr_RoyeDisk_ZakhireNemishavad` قفلش کرده.
- ⚠️ **«بعداً» برداشته نشود**: برنامه باید بی‌اینترنت هم کار کند. آن دکمه نام
  و ایمیل را محلی ذخیره می‌کند و می‌رود گامِ دو؛ دفترِ کاربر هیچ‌وقت گروگانِ
  ابر نیست.
- ⚠️ نامِ پمپ و لوکیشن **پیش از** فرستادنِ کد ذخیره می‌شوند و همان لحظه در
  پروفایل و سربرگ دیده می‌شوند — حتی اگر سرور جواب نداد. (سنجهٔ ۱۴ در
  `verify` همین را گرفت: نام ذخیره شده بود ولی صفحه نامِ قبلی را نشان می‌داد.)

## کارِ سرور (ریپوی `shop` — `docs/PUMP-fa.md`)

برنامه این دو مسیر را می‌زند و پاسخ را **دقیقاً مثلِ راهِ گوگل** می‌خواند
(`{ token, refreshToken, user: { email, name } }`)، تا هیچ جای دیگرِ برنامه
فرق نفهمد:

```
POST /api/auth/register   { name, email, password, app: "pump" }
POST /api/auth/login      {       email, password, app: "pump" }
```

⚠️ تا وقتی این دو مسیر روی ابر نباشند، برنامه **دروغ نمی‌گوید**: پاسخِ ۴۰۴ را
به «رمز غلط» ترجمه نمی‌کند، بلکه می‌گوید «سرورِ حساب هنوز ورود با ایمیل و رمز
را ندارد — فعلاً «ورود با گوگل» را بزنید» (`CloudLink.AuthAsync`، کدِ
`no_route`). راهِ گوگل و راهِ «بعداً» تا آن روز کار می‌کنند.

و فعال‌سازی حالا نام و لوکیشنِ پمپ را هم می‌برد، تا ابر همان پمپ را با همان
نام و لوکیشن بشناسد:

```
POST /api/pump/device/activate
{ code, device{…}, station: { code, name, location } }
```

`location` تازه است؛ سرورِ قدیمی آن را نادیده می‌گیرد و چیزی نمی‌شکند.
